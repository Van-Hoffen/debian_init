# Использование debian_init

Подробное описание шагов, пакетов, пользовательских файлов, бэкапов,
диагностики, дополнительных компонентов и рисков LVM.

Краткий обзор и быстрый старт — в [README](../README.md). Все параметры —
`./install.sh --help`.

## Шаги

| Шаг | Что делает |
|---|---|
| `preflight` | Проверяет ОС и платформу, правит источники APT (отключает `cdrom:`, для Debian при необходимости создаёт `debian.sources`), выполняет `apt-get update` |
| `upgrade` | `apt-get full-upgrade` неинтерактивно; в режиме `existing` `autoremove` не запускается; при необходимости помечает перезагрузку |
| `packages` | Ставит пакеты из `base.list` и списка под платформу; отсутствующие в репозиториях пропускает с предупреждением |
| `system-files` | Раскладывает `/etc/bash/*`: алиасы, welcome-экран, логотипы, список сервисов. `.server_info` не перезаписывает |
| `dotfiles` | Ставит `.bashrc` и `.tmux.conf` в `/root` и `/etc/skel`; старые версии сохраняет |
| `users` | Обновляет `.bashrc` и `.tmux.conf` у локальных пользователей: UID ≥ `UID_MIN`, есть домашний каталог и интерактивная оболочка |
| `hostname` | Меняет имя через `hostnamectl` или `/etc/hostname`, правит `127.0.1.1` в `/etc/hosts` и `/etc/mailname`, если он есть |
| `identity` | Пересоздаёт `machine-id`; если установлен `openssh-server`, пересоздаёт SSH host keys |
| `lvm` | Переименовывает корневую VG в `<hostname>-vg`: показывает diff, просит подтверждение, обновляет initramfs и GRUB, откатывается при ошибке |
| `zabbix` | Настраивает `zabbix-agent2`, если задан `--zabbix-server`; иначе в интерактивном режиме может предложить указать адрес |
| `extras` | Ставит дополнительные компоненты по `--extras` или после интерактивного вопроса |

`preflight` выполняется всегда, в том числе с `--only` и `--skip`.

## Пакеты

Списки лежат в `packages/*.list`: одно имя на строку, `#` — комментарий.

| Платформа | Список |
|---|---|
| `none`, `hw` | `base.list` + `hw.list` |
| `vm`, `kvm` | `base.list` + `vm-kvm.list` |
| `microsoft` | `base.list` + `vm-microsoft.list` |
| `vmware` | `base.list` + `vm-vmware.list` |
| контейнеры (`lxc`, `docker`, `podman`, `systemd-nspawn`, `openvz`, `wsl`) | только `base.list` |
| другая виртуализация | `vm-<virt>.list`, если файл существует |

По умолчанию платформа определяется через `systemd-detect-virt`; `--platform
auto` оставляет автоопределение.

Установка пакетов не должна ломать уже работающую машину:

- по умолчанию apt **не удаляет** ранее установленные пакеты (`--no-remove`).
  Если для установки чего-то из списка требуется удаление (например, агента
  хостера), такие пакеты пропускаются с предупреждением. Разрешить удаление:
  `--allow-remove`;
- если пакетная установка всё же упала (сломанный `prerm`/`postinst` чужого
  пакета, конфликт), apt повторяет установку по одному пакету: сбой одного не
  мешает остальным;
- перед повтором выполняется `dpkg --configure -a`, итоговый список
  неустановленных пакетов выводится в сводке.

Учтены изменения Debian 13: `last` удалён из `util-linux`, вместо него ставится
`wtmpdb`. Пакет `fastfetch` отсутствует в Debian 12 и будет пропущен.

## Пользовательские файлы

`.bashrc` и `.tmux.conf` копируются в каждый домашний каталог — пользователь
может их править. При следующем запуске шага `users` или `dotfiles` они будут
обновлены, старая версия сохранится. Личные правки лучше держать в файлах,
которые установщик не трогает:

| Файл | Подключается из | Назначение |
|---|---|---|
| `~/.bashrc.local` | `.bashrc`, в конце | Любые личные настройки |
| `~/.user_aliases` | `/etc/bash/.bash_aliases` | Личные алиасы; редактировать и применить: `ebal` |
| `~/.tmux.local.conf` | `.tmux.conf`, в конце | Личные настройки tmux |

Если файл в домашнем каталоге — символическая ссылка, установщик пропускает
его с предупреждением (защита от подмены ссылкой на `/etc/shadow` и т.п.).
Запись выполняется от имени владельца каталога через `runuser`.

## Бэкапы и лог

- Пользовательские файлы: рядом, нумерованные копии `.bashrc.~1~`,
  `.bashrc.~2~`…; создаются только если содержимое действительно меняется.
- Системные файлы (`/etc/hosts`, `/etc/fstab`, конфиги GRUB и т.д.):
  `/var/backups/debian_init/<дата-время>/<исходный путь>`.
- Лог: `/var/log/debian_init.log`. В `--dry-run` лог не пишется.
- Повторный запуск идемпотентен: неизменившиеся файлы не перезаписываются.
- Одновременный запуск двух копий блокируется (`/run/debian_init.lock`,
  резервный путь — `/tmp/debian_init.lock`).

## Диагностика и устранение проблем

Сначала посмотрите план и лог:

```bash
./install.sh --mode existing --dry-run
tail -n 100 /var/log/debian_init.log
ls -l /var/backups/debian_init/
```

Скрипт завершается с кодом ошибки и печатает строку, на которой она
произошла. Полный вывод — в логе.

**`preflight`: `apt-get update` завершился с ошибкой.** Проверьте сеть,
DNS и `/etc/apt/sources.list*`; для Debian можно удалить `debian.sources` и
повторить запуск — `preflight` создаст его заново.

**`Could not get lock /var/lib/dpkg/lock-frontend`.** Другой процесс
(`apt`, `unattended-upgrades`) уже работает. Дождитесь его завершения; не
удаляйте lock-файлы вручную.

**Пакет пропущен с предупреждением.** Его нет в репозиториях текущего релиза
или для установки требуется удаление другого пакета. Проверьте вывод apt и
осознанно решите, нужен ли `--allow-remove`.

**`dpkg: error ... old <пакет> package prerm maintainer script subprocess
failed`.** Сломан скрипт удаления стороннего пакета (часто агент хостера,
например `beget-agent`), из-за чего apt не может завершить транзакцию. Скрипт
не падает: проблемные пакеты пропускаются, остальные ставятся. Если удалить
такой пакет нужно осознанно (агент хостера может отвечать за мониторинг и
резервное копирование):

```bash
# посмотреть, что делает сломанный скрипт удаления
less /var/lib/dpkg/info/beget-agent.prerm
# убрать его (dpkg пропустит отсутствующий prerm) и удалить пакет
mv /var/lib/dpkg/info/beget-agent.prerm{,.bak}
dpkg --purge beget-agent
./install.sh --mode existing
```

**Нужно повторить только один шаг.** Используйте `--only` или `--skip`,
например `./install.sh --only packages` или
`./install.sh --skip upgrade --mode existing`. Помните, что `preflight`
выполняется всегда.

**После установки требуется перезагрузка.** Скрипт пишет об этом в конце.
Проверить причину:

```bash
cat /var/run/reboot-required 2>/dev/null || true
cat /var/run/reboot-required.pkgs 2>/dev/null || true
```

**Сервис не работает после настройки.** Проверьте
`systemctl --failed` и `journalctl -u <unit> -b --no-pager`.

## Дополнительные компоненты (`--extras`)

`--extras all` ставит всё. Без `--extras` скрипт спрашивает в интерактивном
режиме. Компоненты ставятся для пользователя `--extras-user`, иначе для
`SUDO_USER`, иначе для единственного обычного пользователя (или скрипт
спрашивает).

| Компонент | Что делает |
|---|---|
| `gitconfig` | `user.name`, `user.email`, редактор, `push.default`, `init.defaultBranch`; данные — из `--git-name`/`--git-email` или вопросов |
| `dirs` | Создаёт `~/Projects`, `~/Documents`, `~/Downloads`, `~/Temp`, `~/Scripts` |
| `sshperms` | Выставляет `700` на `~/.ssh`, `600` на ключи, `644` на `*.pub` |
| `fzf` | Ставит `fzf`, подключает привязки в `~/.bashrc.local` |
| `python` | Ставит `python3`, `python3-pip`, `python3-venv`, `python3-dev` и `pipx`, запускает `pipx ensurepath` |
| `node` | Ставит nvm и LTS Node.js; требует сеть |
| `docker` | Подключает официальный репозиторий Docker (deb822), ставит Docker CE; добавляет пользователя в группу `docker` |
| `zsh` | Ставит oh-my-zsh, powerlevel10k и плагины; меняет оболочку только после подтверждения |

Для `node`, `docker` и `zsh` нужен доступ в интернет. Для `docker` требуется
повторный вход пользователя, чтобы применилась группа.

## Переименование VG: риски

Переименование группы томов корневой ФС — операция, после которой ошибка в
`fstab`/`crypttab`/initramfs/GRUB означает незагружаемую систему. Скрипт:

- показывает diff всех изменяемых файлов и просит подтверждение перед
  `vgrename`;
- откатывает имя VG и файлы при ошибке до завершения шага;
- обновляет initramfs для всех ядер и `grub.cfg`;
- не переименовывает VG, если `/boot` лежит в той же VG, и предупреждает об
  этом;
- не трогает систему, если корень не на LVM.

Перед запуском на важной машине сделайте снапшот ВМ. После переименования
перезагрузка обязательна.

## Разработка и проверка

```bash
tests/run.sh                 # static + unit + cli + integration
tests/run.sh --tier slow     # полный прогон с пакетами, нужна сеть
tests/run.sh --list
```

Тесты идут в одноразовых Docker-контейнерах; репозиторий монтируется только на
чтение. План и матрица покрытия — в [test-plan.md](test-plan.md), список
утверждений — `tests/manifest.yaml`. Статические проверки (`bash -n`,
shellcheck, снапшоты `--help`) входят в `tests/run.sh`.

Автотестов, требующих реальной VM (LVM/GRUB/перезагрузка), пока нет — они
запланированы в `docs/test-plan.md` (VM-001…VM-004).
